# 答题助手

划区 → 识别 → 出答案。屏幕框选一块区域，程序持续截屏、用 OCR 认字、
在本地题库里模糊匹配，然后把题目和答案显示在一个置顶浮窗里。

全程离线，不联网（首次安装需下载 OCR 模型），不依赖任何在线服务。

---

## 功能

| 能力 | 说明 |
| --- | --- |
| 多格式题库导入 | Word(.doc/.docx) / Excel / CSV / JSON / TXT / Markdown，编码与真实格式自动识别 |
| PaddleOCR 中文识别 | 默认引擎，中英混排题干识别准确；内置 RapidOCR 作为备用引擎 |
| 模糊搜索 + 相似度评分 | 三路信号融合（编辑距离 / 最佳子串 / 字符二元组），抗错字、抗截断、抗多余空白 |
| 可自定义扫描区域 | 鼠标拖拽框选，支持多显示器，高 DPI 屏坐标不偏移 |
| 常驻半透明识别框 | 点「开始识别」后出现，可拖动位置、拖边缘缩放、滚轮调透明度，无需重新划区 |
| 识别态自动让位 | 开始识别时主面板自动收进任务栏，退出识别框时自动弹回，答题页面不被挡 |
| 低延迟识别 | 默认 120ms 采样一次（最低 50ms），配合帧差检测，画面静止时不重复 OCR |
| 快捷键全键盘操作 | F1~F9 全局热键，任意窗口有效 |
| 离线运行 | 识别与匹配全部在本机完成，不发起任何网络请求 |
| 三进程隔离架构 | 主程序 / 截屏 / 搜索 各自独立，单点故障不影响界面 |

## 快速开始

```
1. 双击 install.bat      安装环境（首次约 3~10 分钟）
2. 双击 run.bat          启动程序
3. 控制面板「题库」页 → 点「生成示例题库」先跑通流程
4. 按 F1 框选题目区域
5. 按 F2 开始识别 → 识别框出现，主面板自动收进任务栏
6. 拖动识别框调整位置/大小 → 点 ✕ 退出识别并唤回主面板
```

浮窗会显示匹配到的题目、选项（答案高亮）、答案和解析。

**重要**：把浮窗拖到扫描区域**之外**。否则程序会拍到自己显示的内容，
形成「识别到自己输出」的死循环。程序检测到重叠时会在状态栏警告。

## 使用说明

### 键盘操作

| 按键 | 作用 |
| --- | --- |
| `F1` | 重新划定扫描区域 |
| `F2` | 开始 / 暂停持续识别 |
| `F3` | 显示 / 隐藏答案浮窗 |
| `F4` | 立即识别一次（不等画面变化） |
| `F5` | 显示 / 隐藏控制面板 |
| `F6` | 清空当前结果 |
| `F7` | 循环切换浮窗透明度 |
| `F9` | 进入 / 退出识别态（识别框 + 主面板让位） |
| `F8` | 退出程序 |

快捷键可在「快捷键」页改成任意组合，例如 `ctrl+alt+q`。

> 全局热键依赖 `keyboard` 库。个别环境可能被安全软件拦截，此时程序
> 自动降级为「窗口内快捷键」——把焦点切到控制面板或浮窗时仍然可用。

### 识别框交互

按 `F2`（或点「开始识别」）后进入**识别态**，屏幕上会出现一个常驻的半透明识别框，
它标出的就是正在扫描的区域；**同时主面板自动收进任务栏**，把答题页面让出来。

| 操作 | 效果 |
| --- | --- |
| 拖动顶部横条 | 移动整个识别框 |
| 拖动四条边 | 缩放识别框（左右边调宽度，上下边调高度） |
| 在框上滚动滚轮 | 调整识别框透明度（每格 5%） |
| 点顶栏 `✕` | **退出识别**：停止识别 + 收起识别框 + 主面板自动弹回 |
| `F9` | 同上，进入 / 退出识别态的键盘入口 |

- 识别框**只在开始识别后出现**，启动程序时不会提前显示（避免误以为已在识别）
- 顶栏文字实时显示状态（`● 识别中` / `❚❚ 已暂停` / `○ 待机`）、尺寸与透明度
- 暂停（`F2`）时识别框**不会消失**，只是顶栏变琥珀色，主面板也保持让位状态，
  方便先调好位置再继续
- 识别框**中间是镂空的**，边框画在扫描区域**之外**，所以永远不会被 OCR 拍进去，
  也不会挡住下面页面的点击
- 拖动松手的瞬间会自动触发一次识别，不用等画面变化
- 拖动产生的改动会立即写盘，重启后位置保持不变
- 位置跑偏了：控制面板「识别设置」→「常驻识别框」→「重置到屏幕中央」

> **主面板让位是可关的**：控制面板「识别设置」→「常驻识别框」→ 取消勾选
> 「主面板 开始识别时最小化到任务栏」，开始识别就不再动窗口。
> 另外如果你是用 `F5` 主动把面板藏起来的，程序会尊重这个状态，不会硬把它拽出来。

### 浮窗交互

- 按住标题栏拖动，右下角 `◢` 调整大小
- 点击「其他候选」里的条目切换查看
- 「复制答案」把题干与答案写入剪贴板
- `⤓` 切换置顶，`✕` 隐藏

### 划区建议

- **只框题干**：一屏多题时，框住当前这道题的题干即可，识别更快更准
- **避开干扰**：不要框到浏览器标签栏、时间、输入法等无关内容
- **字号太小就放大**：在「识别设置」页把「放大倍数」调到 1.5~2.0
- **深色主题**：开启「二值化」效果通常更好

## 题库格式

### Excel / CSV

表头需包含「题目」和「答案」，其余列可选：

| 题型 | 题目 | 选项A | 选项B | 选项C | 选项D | 答案 | 解析 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 单选题 | 示例题干（请替换成你自己的题目）？ | 选项内容甲 | 选项内容乙 | 选项内容丙 | 选项内容丁 | B | 这里是解析文字，可留空。 |

也支持把选项放在一个单元格里，用换行或 `A.` `B.` 之类标记分隔。
`选项 / 选项内容 / options` 都是可识别的列名。

**标准考试模板直接可用**：`题型 / 题目 / 选项 / 答案 / 解析` 会被读取，
`答案乱序 / 阅卷人 / 阅卷类型 / 难度设置` 等列自动忽略。

### JSON

```json
{
  "questions": [
    {
      "question": "示例题干？",
      "answer": "A",
      "options": ["选项内容甲", "选项内容乙", "选项内容丙", "选项内容丁"],
      "type": "单选题",
      "analysis": "这里是解析文字，可留空。"
    }
  ]
}
```

简写形式 `{"题干": "答案"}` 也支持。JSON Lines（`.jsonl`）同样可用。

### Word / TXT / Markdown

支持 `.docx`（OOXML）与 `.doc`（Word 97-2003）两种 Word 文件，
段落式结构，识别这几种标记：

```
1. 示例题干？
A. 选项内容甲
B. 选项内容乙
C. 选项内容丙
D. 选项内容丁
题型：单选题
答案：B
解析：这里是解析文字。
```

也支持 Word 里的两列表格（题目 | 答案）。

**中文办公文档常见的另一种排版**（题号用 `、`，标记用中文方括号）同样可用：

```
【题型】多选题
16、示例多选题的题干（ ）
A、选项内容甲
B、选项内容乙
C、选项内容丙
D、选项内容丁
【答案】ABC
【解析】这里是解析文字。
```

题号 `1、` `1.` `第1题` `(1)`；选项 `A、` `A.` `（A）` `A：`；
答案 `答案：` `参考答案` `【答案】`；解析 `解析：` `【解析】` `【答案解析】`
都能识别。答案与解析写在同一行（`【答案】B【解析】……`）也可以。

`题型` 标记有两种用法，都会正确处理：写在题内（题干/选项之后、答案之前）
时作为该题的题型；写在前一题答案之后时，作为其后各组题的题型。

**扩展名不可信**：`.doc` 与 `.docx` 的真实格式按**文件头**判定
（`D0CF11E0…` = Word 97-2003，`PK…` = OOXML），不按扩展名。
中文办公环境里「另存为 .doc 但名字还叫 .docx」非常常见，
这类文件以前会让导入直接失败，现在会自动走 Word 97 解析器。
`.doc` 解析是纯 Python 实现（依赖 `olefile`），不需要本机装 Word / WPS。

## 参数调优

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 截屏间隔 | 120ms | 调小反应更快、CPU 更高；调大更省资源 |
| 画面变化阈值 | 1.2 | 帧差低于此值就不重新识别。画面静止时不重复 OCR，这是省 CPU 的关键 |
| 相似度阈值 | 58% | 提高可减少误命中，降低可提高召回 |
| 候选数量 Top-K | 5 | 浮窗里显示多少个备选 |
| 最短触发字数 | 6 | OCR 文本短于此长度不触发匹配，避免噪声误命中 |
| 放大倍数 | 1.6× | 小字号识别率的关键 |
| 推理线程 | 4 | OCR 使用的 CPU 线程数，`自动` 会让 Paddle 按核心数铺满线程 |
| 不透明度 | 95% | 浮窗透明度 |
| 识别框不透明度 | 75% | 识别框边框的不透明度，也可在框上滚轮直接调 |
| 识别框边框粗细 | 10px | 加粗更好找，但会占更多屏幕空间 |
| 开始识别时最小化主面板 | 开 | 关掉后开始识别不动窗口 |

调参思路：**先保证识别准确**（尽量框准、放大倍数调够），**再收紧阈值**。
如果经常不命中，先把相似度阈值降到 45% 看看是不是识别文本有问题。

想更跟手就把「截屏间隔」继续下调到 **50ms**（滑杆下限，也是截屏进程的硬下限）。
画面静止时帧差检测会跳过 OCR，所以调小基本只增加抓屏开销（实测 120ms 下截屏进程
只占 0.07 个核）。

但要清楚：**间隔不是瓶颈**。单次 OCR 在典型题干上要 3 秒左右，
把间隔从 300ms 压到 50ms 只能省下几百毫秒的「发现延迟」，
真正的等待是那一趟识别。详见下面「识别速度」一节。

> **注意**：扫描区域里如果有闪烁光标、进度条动画之类的东西，帧差会一直被判定为
> 「有变化」，OCR 就会连续跑。此时要么把这类内容排除出选区，要么把
> 「画面变化阈值」调大（比如 3.0）把抖动过滤掉。

### 识别速度：瓶颈在 OCR，不在截屏间隔

本机实测（PaddlePaddle 3.3.1 / PP-OCRv6_medium，4 线程，oneDNN 关闭）：

| 选区与内容 | 预处理后尺寸 | 文本行 | 单次 OCR 耗时 |
| --- | --- | --- | --- |
| 520×180（典型题干） | 832×288 | 9 | **3.8 s** |
| 760×170（3 行干净题干） | 1216×272 | 4 | **3.3 s** |
| 900×400（整块桌面） | 1440×640 | 36~39 | **12~13 s** |

也就是说：**单行文本的识别成本约 0.3 秒**，`OCR 耗时 ≈ 行数 × 0.3s`。
截屏间隔只决定「画面变化后多久被发现」，真正的等待来自这一趟 Inference。

所以想让答案出得更快，按收益排序：

1. **把选区框小**（只框题干，别框到整块桌面）——收益最大，成比例减少行数
2. **调小「放大倍数」**：从 1.6 降到 1.0 约省 30%，代价是小字号识别率下降
3. **加大「推理线程」**：4 → 8 通常还能再快一些（代价是占更多 CPU）
4. 换更小的 OCR 模型（如 mobile 版）——需要在联网环境重新下载模型，
   属于可选优化，默认未启用

状态栏会持续显示 `OCR xxx ms/次`，这是判断「慢在哪」最直接的依据。

> **为什么 CPU 占用会很高？** 如果选区里文本很多（比如整块桌面 30+ 行），
> 单次 OCR 要十几秒，搜索进程就会一直满负荷跑（4 线程 ≈ 4 个核）。
> 这是「识别追不上截屏」的表现，不是泄漏——把选区调小即可恢复正常。

## 架构

```
                        ┌──────────────────────────────┐
                        │  主进程 main.py               │
   全局热键 ──────────►  │  Tkinter UI + 配置 + 编排      │
                        └───────────┬──────────────────┘
                                    │ region / interval / thresholds (共享内存)
                                    ▼
   ┌─────────────────┐   frame_q   ┌─────────────────┐   result_q   ┌──────────┐
   │ 截屏进程         │ ──────────► │ 搜索进程         │ ──────────► │ 答案浮窗  │
   │ mss 抓屏         │  只传有变化  │ OCR + 模糊匹配    │             │ 控制面板  │
   │ 帧差检测         │  的画面      │ 题库常驻内存      │             └──────────┘
   └─────────────────┘             └─────────────────┘
```

三个进程只通过 `Queue / Event / Value` 通信，不共享 Python 对象：

- **截屏进程**：以固定节奏抓屏，帧差低于阈值就跳过，`frame_q` 容量为 2
  且满时丢旧帧，保证 OCR 永远只处理最新画面，不会被积压拖垮。
- **搜索进程**：OCR 模型与题库都在这里加载。PaddleOCR 初始化会占用数百 MB
  内存且可能因原生库崩溃，隔离后即便它挂掉也不会带走界面。
  取帧后会先丢掉队列里已被更新的旧帧再识别，保证结果对应的是「当前屏幕」；
  OCR 推理线程默认封顶 4 条（「识别设置」可调），避免 Paddle 按核心数铺满线程。
- **主进程**：只做 UI 与编排，任何耗时操作都不阻塞 Tk 事件循环。
  识别态下的窗口让位（最小化 / 唤回）也由它负责。

### 匹配算法

`core/matcher.py` 里三条信号加权融合：

| 信号 | 权重 | 作用 |
| --- | --- | --- |
| `fuzz.ratio` | 0.42 | 整体编辑距离，抗错别字 |
| `partial_ratio` × 长度惩罚 | 0.26 | 抗 OCR 截断/多余行，长度差大时降权防虚高 |
| 字符二元组 `token_set_ratio` | 0.32 | 中文无词边界，二元组抗中间抖动最强 |

另有两条经验规则：一方完全包含另一方时直接给高置信；查询过短时降权，
避免「下列说法正确的是」这类通用句乱命中。

题库超过 1500 条时自动启用字符二元组倒排索引，把每次比对的候选从
全量压到约 400 条，保证单次匹配停留在毫秒级。

## 部署到其他电脑

### 方式一：生成离线安装包（推荐，目标机零依赖）

```
.venv\Scripts\python.exe tools\pack.py
```

产出 `dist_package\AnswerAssistant-1.0.0-win64.zip`（约 346 MB，15500 个文件）。
包里**自带便携 Python、全部依赖和 OCR 模型**，目标电脑上：

1. 拷过去，**完整解压**到任意目录（建议纯英文路径）
2. 双击 `install.bat` —— 重写环境路径 + 校验依赖与模型 + 自检，**全程离线，10 秒内完成**
3. 双击 `run.bat` 启动

不需要预装 Python、不需要联网、不需要管理员权限。**适用范围与使用前提见包内
`安装说明.md`**（操作系统版本、CPU/内存/磁盘要求、目录限制、已知限制、排错）。

打包工具的几个设计点：

- **白名单收集**：`build/ dist/ logs/ data/ __pycache__` 这些开发产物不进包
- **不带开发脚本**：`tools\pack.py`、`tools\slim.py` 依赖 `packaging\` 目录，
  而包里只保留 `install.bat` 与安装说明，带进去会让人误跑出一个残缺的包，故排除
- **不带 `*.pyc`**：压缩后省约 50 MB，代价是目标机首次启动要重建字节码缓存（多花 10~30 秒）
- **模型不落用户目录**：模型放在包内 `models\paddlex\`，由
  `core.config.ensure_bundled_models()` 在导入 paddle 之前把 `PADDLE_PDX_CACHE_HOME`
  指过去；卸载 = 删文件夹，不留痕迹
- **流式写 zip**：不产生第二份 750 MB 的暂存副本

打完包请按上面第 1~3 步在**另一个目录**实测一遍，尤其是 `install.bat`。

#### 瘦身（`tools/slim.py`）与两个「动一下就坏」的坑

```
.venv\Scripts\python.exe tools\slim.py --report     # 只看体积构成
.venv\Scripts\python.exe tools\slim.py --dry-run    # 预览要删什么
.venv\Scripts\python.exe tools\slim.py              # 执行
```

它只删「可再生成」或「只在构建期需要」的东西：`*.pyc`、`*.pdb`、`*.lib/*.exp`、
`*.pyi`、`paddle/include`、`__pycache__`、`build/ dist/`、运行日志、
便携运行时里从不加载的 `idlelib / turtledemo / Tix / Tk demos`，
以及 cv2 里那个 30 MB 的视频编解码库（本程序只截屏，不处理视频）。
实测 `1.20 GB → 754 MB`、`33193 → 15475` 个文件，压缩后 345 MB。

有**两处看着能删、实际一删 OCR 就废**的地方，已在 `slim.py` 里写死为「不要动」：

| 不能动的东西 | 删掉之后的症状 |
| --- | --- |
| `.venv\...\paddle\utils\cpp_extension\` | `paddle/utils/__init__.py` 在 import 阶段就 `from . import cpp_extension`，删掉后 `import paddle` 直接报 `cannot import name 'cpp_extension' from partially initialized module`，OCR 全线不可用 |
| `opencv-contrib-python`（**不要**换成 `opencv-python-headless`） | PaddleX 的 `is_dep_available()` 是拿 **发行包名** 去查 `importlib.metadata.version()`，而 PaddleOCR 3.x 建流水线时会执行 `pipeline_requires_extra("ocr", alt="ocr-core")`，清单里写的就是 `opencv-contrib-python`。换成 headless 之后 `cv2` 模块照样能 import，但 dist 名字对不上，直接抛 `DependencyError: 'OCR' requires additional dependencies` / `RuntimeError: A dependency error occurred during pipeline creation`——**报错信息完全不提 opencv**，极难定位 |

两条都是踩过的坑，`slim.py` 里有对应的注释说明，不要"优化"掉。

#### 打包后的实测流程

打包 ≠ 可用，必须换目录实测：

```
1. 解压 dist_package\AnswerAssistant-1.0.0-win64.zip 到另一个目录
2. 双击 install.bat      → 重写 pyvenv.cfg、建可写目录、校验依赖与模型
3. 确认 .venv\Scripts\python.exe -c "import sys; print(sys.base_prefix)"
   指向的是【新目录】下的 runtime\python —— 这是可迁移性的关键
4. 跑一遍 tools\selfcheck.py，或直接 run.bat 手动识别一次
```

第 3 步最容易被忽略：`pyvenv.cfg` 里的路径是绝对写死的，**不跑 install.bat
就永远指向打包机上的原路径**，同机器上看着一切正常，换台机器立刻崩。

### 方式二：整个文件夹拷过去（快，但必须重跑安装脚本）

把 `answer-assistant` 整个目录（含 `.venv` 与 `runtime`）拷到目标电脑，然后：

```
双击 install.bat        ← 关键一步，别省
```

**为什么必须重跑**：虚拟环境把基解释器路径**绝对写死**在 `.venv\pyvenv.cfg` 的
`home=` 里。换路径之后 `.venv\Scripts\python.exe` 会去找旧路径的运行时——
同一台机器上会悄悄用回旧的那套（看不出问题，但很危险），换台机器直接起不来。
包里的 `install.bat` 会调用 `tools\setup_env.py` 把这三行改成指向本目录的
`runtime\python`。

顺带说：`tools\setup_env.py` 用 `mbcs`（本地代码页）写 `pyvenv.cfg`，
因为 CPython 启动阶段就是按本地代码页解析它的；路径含中文时用 UTF-8 写会变乱码。

### 方式三：只拷源码，在目标电脑上联网安装

拷贝除 `.venv`、`runtime`、`logs`、`data` 之外的所有文件，然后双击 `install.bat`：

1. 找本机带 tkinter 的 Python（3.9+）；
2. 找不到就下载便携运行时到 `runtime\python`（**不需要管理员权限**，不改 PATH）；
3. 建虚拟环境 `.venv`；
4. 装依赖和 OCR 引擎（默认走清华镜像，失败自动回落官方源，约 400 MB）；
5. 跑一遍自检。

模型会在第一次识别时自动下载（约 156 MB），所以这种方式**必须联网**。

### 打包成 exe（不推荐）

```
双击 build_exe.bat
```

会产出 `dist\AnswerAssistant\`。PaddleOCR 依赖大量动态库与模型文件，
打出来约 1.5~2 GB，且 `--onefile` 模式下 Paddle 的原生库容易加载失败，
所以脚本固定用 `--onedir`。

**单文件夹 exe 比方式一的离线包更大、更容易出兼容问题**，除非对方明确要求
「一个可执行文件」，否则用方式一。

## 常见问题

**Q：启动后提示「没有可用的 OCR 引擎」**

先跑 `run_debug.bat` 看日志，或执行：

```
.venv\Scripts\python.exe tools\selfcheck.py
```

最常见的原因是首次运行需要联网下载模型（约 140MB）。若日志里出现
`ConvertPirAttribute2RuntimeAttribute not support`，那是 PaddlePaddle 3.3
的 oneDNN 兼容性问题——程序已默认关闭 oneDNN 并会在预热时自动切换，
如果仍失败请把「启用 oneDNN」保持关闭并重启程序。

**Q：识别出来是乱码 / 识别不到字**

- 检查扫描区域是否真的框住了文字（浮窗里会显示识别到的原始文本，一看便知）
- 把「放大倍数」调到 1.5~2.0
- 深色底浅色字：开启「二值化」
- 字号极小（小于 12px）：先放大系统缩放或页面缩放

**Q：匹配不到题目**

- 确认题库已导入（控制面板「题库」页会显示总题数）
- 把「相似度阈值」降到 45%~50%
- 看浮窗里的「识别到的文字」，如果 OCR 结果本身就不对，先解决识别问题

**Q：浮窗挡住了题目**

拖开它。程序检测到浮窗与扫描区域重叠时会在状态栏警告。

**Q：答案框里的选项错位，显示成 `A. A` / `C. B` 这种**

已修复。原因是「选项」列里用换行分隔的 `A. …/B. …` 文本在拆分时，
正则的捕获组会被 `re.split` 一并塞进结果列表，导致字母被当成选项正文，
答案随之渲染成 `C. B`。修好后浮窗会显示完整选项正文，比如
`C. 选项内容丙`。

如果你手上还有旧版程序：升级后**重新导入一次题库**即可（题库是启动时读文件，
没有缓存，重启程序就会重新解析）。自检里的「选项拆分」「各格式选项完整性」
两项会持续守住这个问题。

**Q：按 F2 之后控制面板不见了**

这是设计如此——识别态会把主面板收进任务栏给答题页面让位。
点识别框顶栏的 `✕` 或按 `F9` 退出识别，主面板就会自动弹回来。
不想让它自动让位，可在「识别设置」→「常驻识别框」里取消勾选
「主面板 开始识别时最小化到任务栏」。

**Q：识别框上的 ✕ 点了没反应**

已修复（`✕` 的点击事件此前的绑定被后续绑定覆盖了）。
若你用的是旧版本，请更新 `ui/capture_frame.py`。

**Q：按 F1~F8 没反应**

全局热键被拦截了。切到控制面板窗口内再按，或者用界面按钮操作。
也可以试试以管理员身份运行 `run.bat`。

**Q：CPU 占用偏高**

1. 把「推理线程」设成 4 或更低（`自动` 会让 Paddle 按核心数铺满线程，
   这是最常见的元凶）
2. **把选区框小**——OCR 耗时与文本行数近似成正比，整块桌面 30+ 行要十几秒，
   只用题干那几行只要 3 秒出头
3. 把「截屏间隔」调到 500ms 以上
4. 把「画面变化阈值」调到 3.0

画面静止时程序本来就不会重复 OCR。如果扫描区域里有闪烁光标或动画，
帧差会一直被判定为「有变化」，此时请把这类内容排除出选区。
状态栏的 `OCR xxx ms/次` 能直接告诉你是识别慢还是截屏慢。

**Q：高缩放屏（125%/150%）下选区偏移**

程序启动时已开启 Per-Monitor DPI 感知，正常情况下不会偏移。
若确实偏移，检查是否有其它进程改过 DPI 设置，重启程序即可。

## 环境要求

- Windows 10 1803 及以上（需要系统自带 `curl` 与 `tar` 以便自动获取运行时）
- 64 位系统
- 首次安装需要网络；之后可完全离线
- 内存建议 4GB 以上（PaddleOCR 常驻约 400~700MB）

Python 版本由 `install.bat` 自动处理。若手动安装，请注意：

- Python **3.9 ~ 3.13** 均可，但运行环境**必须带 tkinter**（python.org
  官方安装包默认包含；某些精简版/嵌入式发行版不带）
- 若用 Python 3.13，RapidOCR 的 ONNX 后端不可用（`rapidocr-onnxruntime`
  声明 `<3.13`）。可改用 `pip install rapidocr-openvino`，
  或直接依赖 PaddleOCR——默认配置下这不影响使用

## 使用范围

这是一个**自学与练习辅助工具**：用来核对练习题的答案、查漏补缺、
把题库变成随手可查的速查表。

请把它用在自学、复习、模拟练习等场景。用于正式考试属于作弊行为，
既违反考试规则，也让自己失去了真正掌握知识的机会 ——
尤其像要动手排障的技术方向，考场上蒙对不等于现场会修。

题库文件由使用者自己提供，程序不内置、不联网获取任何题库。
